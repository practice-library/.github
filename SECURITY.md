# Security policy

## Reporting a vulnerability

Please report security problems privately through GitHub's private vulnerability reporting, not in a public issue:

1. Open the affected repository's **Security** tab.
2. Choose **Report a vulnerability**.
3. Describe what you found and how to reproduce it.

Only the maintainers see the report. We will work with you on a fix in a private advisory and credit you when it is published, unless you would rather not be named.

## What counts

- A leaked secret, token or key in any file, history or workflow log.
- A workflow that could run untrusted code with write access or with secrets.
- A way to make the verification of research answers accept a source or claim it should reject.
- A vulnerability in code published here, or in a dependency it pins.

A wrong or outdated fact in the library is not a security problem: please open a correction issue instead.

## Supported versions

Fixes go to the default branch and to the latest edition only.
